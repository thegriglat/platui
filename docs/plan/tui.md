# План модуля tui — TUI для Plane

## 1. Цель
Консольное приложение `platui` (Go) для работы с Plane (plane.so, облако и self-hosted) через публичный REST API:
просмотр проектов и задач (work items), просмотр карточки задачи, базовая правка, создание задачи
и — дополнительная фича — создание git-ветки в текущем репозитории прямо из выбранной задачи.

## 3. Решения главной сессии (по умолчанию, можно пересмотреть шлюзом)
- Go-модуль: `platui`; бинарь `cmd/platui`; код в `internal/`.
- Конфиг: путь `--config`, иначе `$XDG_CONFIG_HOME/platui/config.yml` (`~/.config/platui/config.yml`). Поля (точный формат — в контракте):
  `base_url` (по умолчанию `https://api.plane.so`), `api_key` или `api_key_env` (имя переменной окружения), `workspace` (slug),
  `default_project` (identifier, необязательно), `branch.template` (по умолчанию `{identifier}-{sequence}-{slug}`), `branch.base` (необязательно; пусто — текущий HEAD), `branch.checkout` (bool, по умолчанию true).
- Авторизация — заголовок `X-API-Key`. Учитывать лимит запросов API (проверить в документации) и пагинацию.
- Git — через CLI `git` (`os/exec`), не go-git: уважает настройки и хуки пользователя. Репозиторий — текущий каталог (флаг `--repo` переопределяет).
- Имя ветки: slug из названия задачи — латиница/цифры/дефис, нижний регистр, кириллица транслитерируется, длина slug ≤ 40; ветка уже есть — предложить переключиться на неё, не падать.
- Без внешних сервисов в тестах: API — `httptest`, git — временный репозиторий.

## 4. Скоуп MVP
Экраны и действия TUI:
- список проектов workspace → выбор проекта (или сразу `default_project`);
- список задач проекта: идентификатор (`PROJ-12`), название, состояние, приоритет, исполнители; фильтр по состоянию, поиск по тексту (`/`), обновление из API (`R`);
- карточка задачи: описание (HTML → текст), состояние, приоритет, исполнители, метки, комментарии (только чтение);
- действия: сменить состояние, сменить приоритет, назначить на себя, создать задачу (название + описание), открыть в браузере, **создать git-ветку** (`b`: показать имя по шаблону, дать отредактировать, создать/переключиться, итог в статусной строке);
- справка по клавишам (`?`), выход (`q`).
Вне скоупа: циклы, модули Plane, страницы, вложения, правка комментариев, офлайн-кэш.

### 4.1. Расширенный скоуп (решение пользователя 2026-10-20: все пункты TODO.md — в работу)
Git и процесс: задача по текущей ветке при запуске; «старт работы» одной клавишей (ветка + In Progress + назначить на себя); ветка в `git worktree`; подготовка коммита (`PROJ-42: <название>` — шаблон сообщения / `prepare-commit-msg` hook); «готово к ревью» (push + PR через `gh`/`glab`, ссылка комментарием, In Review); признак ветки в списке задач (локальная/удалённая, ahead); уборка веток закрытых задач с подтверждением.
Клавиатура: палитра команд (`:`/`Ctrl+P`, нечёткий поиск по задачам, проектам, действиям); переход по ID (`g`+номер); ~~vim-клавиши~~ — не нужны (решение пользователя 2026-10-20: стрелки, Tab, Shift/Ctrl/Alt); массовые действия (отметка `space`, смена состояния/исполнителя/метки); сохранённые фильтры в конфиге, переключение `1…9`; канбан-вид (колонки по состояниям, перенос `H/L`).
Текст: описание/комментарий в `$EDITOR` (Markdown → HTML для Plane); создание задачи одной строкой (`fix login !high @me #bug`); копирование в буфер через OSC 52 (ID, ссылка, название, имя ветки, `[PROJ-42](url)`); описание с подсветкой Markdown (glamour).
Терминал: режим без интерфейса (`platui ls --mine --json`, `show`, `branch`, `start`); `platui prompt` для промпта/tmux; учёт времени (таймер → комментарий); автообновление и уведомления с учётом лимита API; кэш на диске (старт с кэша, обновление в фоне); ~~несколько workspace/инстансов~~ — отложено (решение пользователя 2026-10-20); темы и цвета в YAML, `NO_COLOR`.
Отсюда §4 «Вне скоупа» не меняется; комментарии теперь можно и создавать (через `$EDITOR`).
