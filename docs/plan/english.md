# План модуля english — английский язык и установка одной командой

## 1. Цель
Публичный проект на одном языке: все комментарии в коде, тексты интерфейса TUI и CLI, сообщения об ошибках,
`config.example.yml` и README — на английском. Установка одной командой `go install github.com/thegriglat/platui@latest`.

## 2. Решения пользователя
- README и комментарии в конфиге — на английском; вообще все комментарии — на английском (2026-10-20).
- Тексты интерфейса (статусная строка, справка, диалоги, подсказки, сообщения CLI и ошибки) — тоже на английском, без механизма переводов (2026-10-20).
- `main` — в корень модуля, чтобы работал `go install github.com/thegriglat/platui@latest`; `platui version` — версия из build info (2026-10-20).

## 3. Решения главной сессии
- Переводить смысл, не дословно: идиоматичный технический английский, стиль godoc (комментарий экспортируемого имени начинается с имени).
- Не менять поведение: только текст комментариев и строковых литералов, без рефакторинга; клавиши, форматы, коды выхода — как есть.
- Тестовые данные с кириллицей, которые проверяют поведение (транслитерация slug, поиск по кириллице, разбор Markdown/HTML с кириллицей, todo-файлы) — остаются; тесты, сверяющие тексты UI, обновляются вместе с текстами.
- Строки, на которые ссылаются другие пакеты (`app.CertHint` и др.), — их владелец переводит, потребители обновляют свои тесты в своей задаче; общий прогон `go test ./...` — после слияния всех задач.
- Документы журнала dpcli (`docs/plan`, `docs/contracts`, `docs/research`) и файлы процесса (`.dpcli/`, `.claude/`, `CLAUDE.md`, `TODO.md`) — не трогать, остаются на русском; значения строк, процитированные в контрактах, координатор обновляет в контрактах.
- Сообщения коммитов в git — как раньше (по-русски), это не код.
- Проверка «нет кириллицы»: `grep -rnP '[\p{Cyrillic}]'` по файлам задачи, кроме тестовых данных, перечисленных в отчёте исполнителя.

## 4. Задачи
- **EN-1** (dp-engineer) — `main` в корень: `main.go` пакета main в корне модуля (содержимое `cmd/platui/main.go`, комментарии и строки — сразу на английском), `cmd/` удалить; `platui version` — `debug.ReadBuildInfo()` (`Main.Version`, при `(devel)` — `vcs.revision`/`vcs.modified` из Settings), `-ldflags -X` по-прежнему перекрывает; README и CI — новые команды сборки/установки (`go build -o platui .`, `go install github.com/thegriglat/platui@latest`).
- **EN-2** (dp-engineer) — перевод `internal/tui` (файлы — первая половина по алфавиту) — комментарии, тексты UI, тесты на тексты.
- **EN-3** (dp-engineer) — перевод `internal/tui` (вторая половина по алфавиту).
- **EN-4** (dp-engineer) — перевод `internal/app`, `internal/plane`.
- **EN-5** (dp-engineer) — перевод `internal/cli`, `internal/cache`, `internal/config`, `internal/forge`, `internal/gitbranch`, `internal/httpclient`, `internal/runner`, `internal/search`, `internal/text`, `internal/todo`.
- **EN-6** (dp-writer) — `config.example.yml` (все комментарии) и README (остатки кириллицы, тексты из UI, если цитируются); после EN-1.
- Разбиение `internal/tui` на EN-2/EN-3 и границы файлов — координатор по фактическому размеру.

## 5. Волны
1. EN-1 и EN-2…EN-5 параллельно (файлы не пересекаются; `main.go` — только EN-1).
2. EN-6, затем итоговая проверка: `go build ./... && go vet ./... && go test -race ./...` и grep на кириллицу по всему коду (кроме тестовых данных из отчётов).

## 6. Условия остановки
- Перевод требует изменить поведение или формат (например, ключи конфига, имена команд CLI).
- Неясно, тестовые ли это данные или текст UI, и от этого зависит поведение.
